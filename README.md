# Lis App

Connects an Android phone to a lis desktop over the local network: phone
stats on the PC, files both ways, locking the PC from the phone, and the phone's
camera as an OBS source. It replaces KDE Connect and DroidCam for these.

## Layout

```
core/      Rust, shared: protocol, pairing, TLS, sessions, file transfer
daemon/    Rust, PC: lis-daemon, listens for the phone and serves the shell over a Unix socket
ffi/       Rust: the core as a library for Android, with Kotlin bindings generated by UniFFI
video/     Rust, shared: the camera stream's packets
obs-plugin/  Rust: the "Lis Camera" source for OBS
android/   Kotlin and Compose: the system hooks and the screens
```

The shell side lives in the lis config: `phone/` and `settings/pages/PhonePage.qml`.

## Security

- All traffic is TLS 1.3, both ways, with each device's own self-signed certificate.
- Pairing is numeric comparison: both devices show a 6-digit code, and a person accepts on both.
  The phone commits to its nonce before seeing the PC's, so an attacker can't search for
  certificates that produce a matching code.
- The PC only accepts pairing for 2 minutes after you press Pair, and one phone at a time.
- After pairing, each side pins the other's certificate fingerprint. Until both sides trust each
  other, only hello and pairing messages move: incoming data closes the connection, and outgoing
  data is dropped.
- Keys on the PC are readable only by your user.
- File names from the other device are reduced to a plain name, and nothing is overwritten.

## Build

```sh
./install.sh
```

This installs `lis-daemon` to `~/.local/bin`, restarting it if it's running, installs the OBS plugin,
and builds the app into `output/lis-app.apk`. It doesn't touch the phone. Use `--daemon-only`,
`--plugin-only` or `--apk-only` for less. The plugin also needs OBS's and FFmpeg's headers, and
rebuilding after a major update of either.

It needs Rust, a JDK (17 or newer), and the Android SDK in `~/Android/Sdk` (or `ANDROID_HOME`) with
its licenses accepted and NDK 30.0.16248370. It passes `https_proxy` on to Gradle, as Java ignores
it.

## Use

The PC listens on TCP 47420 and advertises itself over mDNS (UDP 5353). With ufw:

```sh
sudo ufw allow from 192.168.0.0/16 to any port 47420 proto tcp
sudo ufw allow from 192.168.0.0/16 to any port 5353 proto udp
```

1. In the shell: Settings, Phone Sync, turn it on, press Pair.
2. In the app: choose the PC, or enter its address.
3. Check that both show the same code, and accept on both.
4. In the app's Setup list, allow notifications, background use and Autostart.

## Camera

Video only, 1080p at 60 fps (or 30), H.264 from the phone's hardware encoder.

1. In the app, open Camera and press Start. It only runs while that screen is showing, and stops as
   soon as you leave the app or lock the phone.
2. In OBS, add the **Lis Camera** source.

It uses its own encrypted connection on the same port, and only a paired phone can send to it. When
Wi-Fi can't keep up, frames are dropped until the next keyframe rather than the delay growing.

## Test

```sh
cargo test
```

The tests run real TLS on localhost and the real daemon binary, with `hyprctl` and `notify-send`
stubbed. `cargo run -p lis-daemon --example fake_phone` stands in for the phone while working on
the PC side, and can loop a video file as the camera; its header has the command that makes one.

`cargo test -p lis-camera` tests the plugin by loading it through libobs, with no OBS window or
settings. `cargo run -p lis-camera --example watch` decodes the stream without OBS and reports the
frame rate and delay.
